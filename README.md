# Кастомная сезонная корректировка в Python

Данная Python-версия является актуальной и основана на **X-13ARIMA-SEATS**. Предыдущей версией является R-реализация на такой же модели. 

## Описание файлов:

| Файл | Что это |
|---|---|
| `sa_ru.py` | сама библиотека: `sa_ru_batch()`, `sa_ru()`, `sa_ru_make_config()` |
| `run_sa.py` | скрипт запуска - аналог `sa_ru_realization_v3.R`; пути к файлам задаются в нем |
| `bin/` | программа X-13: `x13ashtml` (Mac Apple Silicon) и `x13as_html.exe` (Windows); код сам возьмет нужную |
| `russia_calendar.xlsx` | лист `Sheet1` - производственный календарь, лист `tariff_plan` - план индексаций ЖКУ |
| `dataexample_nonSA.xlsx` | тренировочный файл с данными (м./м. инфляциями): Лист1 — данные, лист `config` — настройки по рядам, лист `help` — расшифровка колонок |
| `dataexample_SA.xlsx` | результат, создастся при запуске |
| `sa_specs/` | папка со спецификациями, если выбрать заморозку спецификаций, создастся при запуске |

Данный репозиторий `python-rewrite` можно полностью скачать себе и разместить в папке, которую затем вы будете использовать в Python.

## Установка

Нужен Python 3.9+ и пакеты `pandas`, `numpy`, `openpyxl`:

```
pip install pandas numpy openpyxl
```

## Как запустить через `run_sa.py`

1. Файл данных: первая колонка — дата (любой формат: `2015M1`, `2015-01`, дата Excel), дальше по колонке на ряд, заголовок = имя ряда. Рядов может быть сколько угодно - один или несколько. Пропусков внутри ряда быть не должно.
2. **Обязательно** для нового файла данных (т.е. это нужно сделать один раз для каждого вашего файла) добавить в него лист настроек с названием `config`. Содержание листа: строка `DEFAULT` + по строке на ряд. Пустая ячейка = как в `DEFAULT`. Без листа `config` код не запустится. Важна настройка `input_type`: `mom_index` нужен для индексов около 100, `log_level` для накопленного лог-уровня, `level` для обычных уровней вроде зарплат, М2 и проч.
3. В `run_sa.py` необходимо указать имя файла в `DATA` и запустить:
   - из терминала:
     ```
     cd "/путь/к/sa_ru_python" && python3 run_sa.py
     ```
   - из Jupyter — две строки в одной ячейке:
     ```
     %cd "/путь/к/sa_ru_python"
     %run run_sa.py
     ```
После запуска будет доступно также саммари с информацией об обнаружении сезонности, порядках модели и проч. Обратите внимание: если `sa_ru.py` редактировался, Jupyter может держать в памяти старую версию. При ошибках можно перезапустить ядро (Kernel → Restart).

4. Результат - Excel `<имя данных>_SA.xlsx` с листами `adjusted` (SA-ряды в том же
   формате и в тех же колонках, что на входе), `seasonal_factor`, `trend`, `summary`.
5. Дальнейшая работа может выглядеть так: каждый месяц пользователь дописывает строки на лист с данными, запускает `run_sa.py`. Если изменение настроек не требуется, лист `config` редактировать не нужно.
6. Если выбрана настройка `freeze = TRUE`, раз в год необходимо идентифицировать модели, затем блок идентификации следует закомментировать и использовать уже оцененные модели (см. далее). 

## Вызов из своего скрипта (не из `run_sa.py`)

Сезонную функцию можно использовать и внутри собственного стороннего Python-кода. 
В том месте, где должно быть сглаживание, нужно написать:

```python
import sys
from pathlib import Path

SA_DIR = Path(r"C:\Users\...\sa_ru_python")   # папка с файлами этого репозитория (Windows)
# SA_DIR = Path("/Users/.../sa_ru_python")    # папка с файлами этого репозитория (Mac)
sys.path.append(str(SA_DIR))                  # "подключить" папку

from sa_ru import sa_ru_batch, sa_ru_make_config

out = sa_ru_batch(
    data_file     = "my_data.xlsx",                    # свой файл: дата + ряды + лист config
    calendar_file = SA_DIR / "russia_calendar.xlsx",   # календарь берется из папки 
)
adjusted = out["adjusted"]                             # date + скорректированные ряды, дальше свой код
```

Файл с данными может лежать где угодно (нужно указать путь). Рядом с ним появится файл `<имя>_SA.xlsx`. 

## Как взять результат в свой код

После запуска (в `run_sa.py` или в своем скрипте) надо написать:
```python
adjusted = out["adjusted"]                    # таблица: date + все SA-ряды
sa_one   = adjusted["Мясопродукты"]           # если нужен один ряд, который назывался Мясопродукты
sa_some  = adjusted[["date", "Сыр", "Яйца"]]  # если нужно несколько рядом
```
Или в любом другом скрипте — из сохранённого файла:
```python
sa = pd.read_excel("inflcomponents_SA.xlsx", sheet_name="adjusted")
```

## Настройки (лист `config`)

Строка `DEFAULT` — настройки для всех рядов. У остальных строк заполняются только те ячейки, которые должны отличаться; пустая ячейка = как в `DEFAULT`.
**Полный список колонок и всех допустимых значений:**

| колонка | допустимые значения | значение по умолчанию | смысл |
|---|---|---|---|
| `series_id` | `DEFAULT` или имя ряда = заголовок колонки с данными |  | к какому ряду относится строка |
| `skip` | `TRUE` / `FALSE` | FALSE | TRUE - ряд не корректировать |
| `input_type` | `mom_index` / `log_level` / `level` | mom_index | 103.7 = +3.7% м/м / накопленный лог-уровень / обычный уровень (зарплаты, М2) |
| `calendar_mode` | `none` / `basic` / `extended` / **`auto`** | basic | без регрессоров / рабочие дни / рабочие дни + праздники / выбрать по информационным критериям |
| `include_easter` | `TRUE` / `FALSE` / **`auto`** | FALSE | регрессор Пасхи; `auto` — выбрать по информационным критериям |
| `freeze` | `TRUE` / `FALSE` | FALSE | заморозить спецификацию модели для исключения эффекта виляния хвостом (значения пересмотра значений при добавлении новой точки) (см. ниже) |
| `transform` | `none` / `log` / **`auto`** | none | логарифмирование; работает только при `input_type = level` (для индексов всегда `none`) |
| `use_outliers` | `TRUE` / `FALSE` | TRUE | автопоиск выбросов AO/LS/TC |
| `outlier_types` | `all` или список через запятую: `ao,ls,tc` | all | какие типы выбросов искать |
| `outlier_critical` | число (например `4`) или пусто | пусто | критическое t для выброса; пусто = порог X-13 по длине ряда |
| `method` | `prefer_seats` / `seats` / `x11` | prefer_seats | SEATS с переходом на X11 при неудаче / только SEATS / только X11 |
| `tariff` | `none` / `schedule` / `regressor` | none | режимы для обработки индексаций тарифов ЖКУ (см. ниже) |
| `tariff_series` | имя колонки с данными | пусто | только для `tariff = regressor`: колонка с м./м. индексом ЖКУ |
| `forecast_months` | целое число | 36 | горизонт прогноза X-13 (нужен для фильтров и регрессоров) |
| `seasonality_alpha` | число от 0 до 1 | 0.05 | уровень значимости QS-теста на сезонность |
| `comment` | любой текст |  | пометки для себя, кодом не читается |

Если написать недопустимое значение, код остановится и скажет, в какой строке и колонке ошибка и что там можно писать.

### Что такое `auto`

`auto` можно поставить в трёх колонках: `calendar_mode`, `include_easter`, `transform`. Это значит «не знаю, выбери сам по информационному критерию (в данном случае AICc)».

Что перебирается при `calendar_mode = auto` и `include_easter = auto`: 
- `none` (нет регрессоров вообще),
- `basic`,
- `basic`+Пасха,
- `extended`,
- `extended`+Пасха. 

Порядок ARIMA и выбросы X-13 подбирает сам **всегда**, независимо от `auto`.

## Заморозка: `freeze` и папка `sa_specs`

Заморозка нужна, чтобы при добавлении новой точки не переписывалась уже посчитанная история (методика Банка России: раз в год фиксируются начало выборки, модель ARIMA и набор выбросов; в текущем году программе разрешено только искать новые выбросы).

Для инфляции рекомендуется следующее:
**Раз в год** — идентификация (в `run_sa.py` это фрагмент):
```python
sa_ru_identify_batch(DATA, CALENDAR, cutoff_date="2025-12")
print(sa_ru_list_specs())     # что заморожено и когда
```
Это значит, что для каждого ряда с настройкой `freeze = TRUE` подбирается модель на данных **по декабрь 2025 включительно** и кладется файл `sa_specs/<имя ряда>.json` с именем файла как у ряда. Внутри информация о преобразовании, режиме календаря, Пасхе, порядке ARIMA, списке выбросов, окне центрирования календаря, самих коэффициентах и контрольной сумме данных периода идентификации.

В 2026 каждый месяц осуществляется **обычный прогон уже оцененных моделей на данных** - за это отвечает дальнейший код в `run_sa.py`. Для рядов с `freeze = TRUE` модель и коэффициенты берутся из `sa_specs`, история не переоценивается или переоценивается минимально. Код может дать предупреждение о том, что ряд надо переидентифицировать, если история ряда отличается от того, на котором производилась идентификация, или если различается набор регрессоров. Исследователь может выбрать: проигнорировать это предупреждение или проверить свои данные. 

В начале следующего года идентификацию повторяют, сдвинув `cutoff_date` на новый декабрь. Старые файлы спецификаций перезапишутся.

**Когда необходимо `freeze = FALSE`:**

- для рядов инфляции по ЖКУ: в предложенном примере модель не требуется в принципе (см. ниже), замораживать нечего;
- новый ряд короче трёх лет - идентификация требует минимум 36 месяцев;
- ряд, с которым вы еще экспериментируете и подбираете настройки.

Таким образом, колонка `freeze` в Excel отвечает за выбор рядов, которых будет касаться заморозка, а часть с идентификацией в `run_sa.py` включает идентификацию в коде для сделанного выбора. Запускать идентификацию каждый месяц не нужно: код будет переидентифицировать модели заново и перезаписывать файлы со спецификацией - это негативно скажется на скорости выполнения кода и, если сдвигать `cutoff_date` каждый месяц, заморозка потеряет смысл. Если пользоваться заморозкой правильно, внутри года ее применение позитивно скажется на скорости выполнения кода. 

## Данные по инфляции: тарифы ЖКУ

Настройка `tariff = schedule` следует выбирать для ряда, который **сам является** тарифами (колонка ЖКУ). Для нее X-13 не используется. По методике Банка России годовой рост ряда распределяется ровно по 12 месяцам календарного года. Для истории берется факт из самого ряда, для текущего года — факт по последний месяц × план на оставшиеся месяцы с листа `tariff_plan`, куда исследователь должен внести опубликованный официально план индексации тарифов. Когда приходит фактический месяц индексации, годовой итог уточняется и все месяцы этого года немного пересматриваются.

Настройку `tariff = regressor` следует выбирать, если исследователь сезонно корректирует **агрегат, внутри которого находятся ЖКУ** (услуги целиком или headline ИПЦ). В X-13 добавляется регрессор из графика индексаций (факт из колонки `tariff_series` + план), центрированный внутри календарного года; коэффициент при нём оценивается, и эффект вычитается из SA-ряда.

### Первая точка ряда

Для `input_type = mom_index` X-13 корректирует уровень цен, а на выходе нужны темпы. Поправка месяца — это изменение сезонного фактора, а для самой первой точки предыдущего месяца в выборке нет. Код оценивает недостающий фактор по тому же календарному месяцу следующего года (сезонные факторы меняются медленно), поэтому первая точка считается так же, как все остальные. Без этого она смещается на величину сезонного фактора. Тем не менее, первый год выборки X-13 оценивает односторонним фильтром (слева данных нет), так что он всегда менее точен, чем середина ряда.

Для `input_type = log_level` и `level` вопрос не возникает: на выходе сам уровень.
