# sa_ru — сезонная корректировка с российским календарём (Python)

Python-версия `sa_ru_functions_v2.R`. Считает **тот же X-13ARIMA-SEATS**, что и
R-пакет `seasonal`, поэтому результаты совпадают с R (проверено: разница 1e-10).

## Что в папке

| Файл | Что это |
|---|---|
| `sa_ru.py` | сама библиотека: `sa_ru_batch()`, `sa_ru()`, `sa_ru_make_config()` |
| `run_sa.py` | скрипт запуска — аналог `sa_ru_realization_v3.R`; пути к файлам задаются в нём |
| `bin/` | программа X-13: `x13ashtml` (Mac Apple Silicon) и `x13as_html.exe` (Windows); код сам берёт нужную |
| `russia_calendar.xlsx` | лист `Sheet1` — производственный календарь, лист `tariff_plan` — план индексаций ЖКУ |
| `inflcomponents_nonSA.xlsx` | лист `Лист1` — данные, лист `config` — настройки по рядам, лист `help` — расшифровка колонок |
| `inflcomponents_SA.xlsx` | результат (создаётся при запуске) |
| `sa_specs/` | замороженные спецификации, по файлу на ряд (создаётся при идентификации) |

Папку можно целиком скопировать коллеге — больше ничего не нужно.

## Установка

Нужен Python 3.9+ и пакеты `pandas`, `numpy`, `openpyxl` (в Anaconda уже есть):

```
pip install pandas numpy openpyxl
```

Программа X-13 ищется так: `bin/` рядом с `sa_ru.py` → переменная окружения
`X13PATH` → папка R-пакета `x13binary` → системный PATH. Скачать для своей ОС:
https://www.census.gov/data/software/x13as.html (нужен один файл-программа).

## Как запустить

1. Файл данных: первая колонка — дата (любой формат: `2015M1`, `2015-01`, дата Excel),
   дальше по колонке на ряд, заголовок = имя ряда. Рядов может быть сколько угодно —
   хоть один, хоть сорок. Ряды могут начинаться в разные месяцы; пропусков внутри
   ряда быть не должно.
2. **Обязательно** один раз (для нового файла данных) добавить в него лист настроек
   (в `run_sa.py` это закомментированная строка в п. 0):
   ```python
   sa_ru_make_config("inflcomponents_nonSA.xlsx")
   ```
   В файле появятся листы `config` (строка `DEFAULT` + по строке на ряд; пустая
   ячейка = как в `DEFAULT`) и `help` (расшифровка колонок). Файл при этом должен
   быть закрыт в Excel. Без листа `config` код не запустится — это защита от
   случайного прогона с чужими настройками (например, инфляционных умолчаний на
   данных по реальному сектору).
3. Открыть лист `config`, проверить строку `DEFAULT` — прежде всего `input_type`
   (`mom_index` для индексов около 100, `log_level` для накопленного лог-уровня,
   `level` для обычных уровней вроде ИПП или зарплат) — и при необходимости
   настройки отдельных рядов.
4. В `run_sa.py` указать имя файла в `DATA` и запустить:
   - из терминала:
     ```
     cd "/путь/к/sa_ru_python" && python3 run_sa.py
     ```
   - из Jupyter — две строки в одной ячейке, каждая со своим `%` (обычный `cd` и
     `&&` в ноутбуке не работают):
     ```
     %cd "/путь/к/sa_ru_python"
     %run run_sa.py
     ```
     После `%run` переменные скрипта (`out`, `adjusted`, `summary`) доступны в
     следующих ячейках ноутбука. Если `sa_ru.py` правили, Jupyter может держать в
     памяти старую версию — `run_sa.py` перезагружает модуль сам, но при странных
     результатах надёжнее перезапустить ядро (Kernel → Restart).

   Результат — Excel `<имя данных>_SA.xlsx` с листами `adjusted` (SA-ряды в том же
   формате и в тех же колонках, что на входе), `seasonal_factor`, `trend`, `summary`.
5. Дальше каждый месяц: дописать строки на лист с данными, запустить `run_sa.py`.
   Лист `config` не трогать.
6. Если пользуетесь заморозкой (`freeze = TRUE`) — раз в год прогнать идентификацию,
   см. раздел «Заморозка».

## Вызов из своего скрипта (не из `run_sa.py`)

Если сезонка нужна внутри собственного кода, лежащего где угодно, — в том месте,
где должно быть сглаживание, пишете:

```python
import sys
from pathlib import Path

SA_DIR = Path(r"C:\Users\Иван\Documents\sa_ru_python")   # папка с сезонкой (Windows)
# SA_DIR = Path("/Users/ivan/Documents/sa_ru_python")    # то же для Mac
sys.path.append(str(SA_DIR))                               # "подключить" папку

from sa_ru import sa_ru_batch, sa_ru_make_config

# не забудьте добавить лист config. в нем обязательно должна быть первая строчка DEFAULT

out = sa_ru_batch(
    data_file     = "my_data.xlsx",                    # свой файл: дата + ряды + лист config
    calendar_file = SA_DIR / "russia_calendar.xlsx",   # календарь берётся из папки сезонки
)
adjusted = out["adjusted"]                             # date + посезоненные ряды, дальше свой код
```

Три строки с `SA_DIR` / `sys.path.append` / `from sa_ru import` — это
подключение к папке. Файл с данными может лежать где угодно (указать путь);
рядом с ним появится `<имя>_SA.xlsx`. 

## Как взять результат в свой код

Прямо после запуска (в `run_sa.py` или в своём скрипте) надо написать:
```python
adjusted = out["adjusted"]                    # таблица: date + все SA-ряды
sa_one   = adjusted["Мясопродукты"]           # если нужен один ряд
sa_some  = adjusted[["date", "Сыр", "Яйца"]]  # если нужно несколько
```
Или в любом другом скрипте — из сохранённого файла:
```python
sa = pd.read_excel("inflcomponents_SA.xlsx", sheet_name="adjusted")
```

## Настройки (лист `config`)

Строка `DEFAULT` — настройки для всех рядов. У остальных строк заполняются только
те ячейки, которые должны отличаться; пустая ячейка = как в `DEFAULT`.
**Полный список колонок и всех допустимых значений:**

| колонка | допустимые значения | по умолчанию | смысл |
|---|---|---|---|
| `series_id` | `DEFAULT` или имя ряда = заголовок колонки с данными | — | к какому ряду относится строка |
| `skip` | `TRUE` / `FALSE` | FALSE | TRUE — ряд не сезонить, в выход попадёт как есть |
| `input_type` | `mom_index` / `log_level` / `level` | mom_index | 103.7 = +3.7% м/м / накопленный лог-уровень / обычный уровень (ИПП, зарплаты, М2) |
| `calendar_mode` | `none` / `basic` / `extended` / **`auto`** | basic | без регрессоров / рабочие дни / рабочие дни + праздники / выбрать по AICc |
| `include_easter` | `TRUE` / `FALSE` / **`auto`** | FALSE | регрессор Пасхи; `auto` — выбрать по AICc |
| `freeze` | `TRUE` / `FALSE` | FALSE | считать по замороженной модели из папки `sa_specs` (см. ниже) |
| `transform` | `none` / `log` / **`auto`** | none | логарифмирование; работает только при `input_type = level` (для индексов всегда `none`) |
| `use_outliers` | `TRUE` / `FALSE` | TRUE | автопоиск выбросов AO/LS/TC |
| `outlier_types` | `all` или список через запятую: `ao,ls,tc` | all | какие типы выбросов искать |
| `outlier_critical` | число (например `4`) или пусто | пусто | критическое t для выброса; пусто = порог X-13 по длине ряда |
| `method` | `prefer_seats` / `seats` / `x11` | prefer_seats | SEATS с переходом на X11 при неудаче / только SEATS / только X11 |
| `tariff` | `none` / `schedule` / `regressor` | none | тарифы ЖКУ, см. раздел ниже |
| `tariff_series` | имя колонки с данными | пусто | только для `tariff = regressor`: колонка с м/м индексом ЖКУ |
| `forecast_months` | целое число | 36 | горизонт прогноза X-13 (нужен для фильтров и регрессоров) |
| `seasonality_alpha` | число от 0 до 1 | 0.05 | уровень значимости QS-теста на сезонность |
| `comment` | любой текст | — | пометки для себя, кодом не читается |

Если написать недопустимое значение, код остановится и скажет, в какой строке и
колонке ошибка и что там можно писать.

### Что такое `auto`

`auto` можно поставить в трёх колонках: `calendar_mode`, `include_easter`, `transform`.
Это значит «не знаю, выбери сам по информационному критерию».

Информационный критерий (здесь AICc) — это оценка «насколько хорошо модель описала
ряд» со штрафом за каждый лишний регрессор. Чем меньше, тем лучше. Лишний регрессор
всегда чуть-чуть улучшает подгонку, поэтому критерий берёт с него «плату»: если
объяснил мало, а параметр потратил — значение вырастет, и вариант проиграет. Сравнивать
значения между собой имеет смысл только для одного и того же ряда.

Что перебирается при `calendar_mode = auto` и `include_easter = auto`: `none`,
`basic`, `basic`+Пасха, `extended`, `extended`+Пасха (в режиме `none` регрессоров
нет вообще, включая Пасху). Преобразование и набор выбросов при этом фиксируются
по опорной модели, чтобы кандидаты сравнивались на равных. Порядок ARIMA и выбросы
X-13 подбирает сам **всегда**, независимо от `auto`.

Разница в AICc между вариантами обычно невелика (единицы при значениях в тысячи),
поэтому при добавлении новой точки выбор может перескочить с одного варианта на
другой и SA-ряд слегка дёрнется. Поэтому правильно так: один раз прогнать `auto`
при идентификации, а дальше заморозить (см. ниже).

## Заморозка: `freeze` и папка `sa_specs`

Чтобы при добавлении новой точки не переписывалась уже посчитанная история
(методика Банка России: раз в год фиксируются начало выборки, модель ARIMA и набор
выбросов; в текущем году программе разрешено искать новые выбросы самой).

**Раз в год** — идентификация (в `run_sa.py` это п. 0б):
```python
sa_ru_identify_batch(DATA, CALENDAR, cutoff_date="2025-12")
print(sa_ru_list_specs())     # что заморожено и когда
```
Для каждого ряда с `freeze = TRUE` подбирается модель на данных **по декабрь 2025
включительно** и кладётся файл `sa_specs/<имя ряда>.json` — имя файла ровно такое
же, как имя ряда. Внутри: преобразование, режим календаря, Пасха, порядок ARIMA,
список выбросов, окно центрирования календаря, **сами коэффициенты** (календарные
беты, величины выбросов, AR/MA) и контрольная сумма данных периода идентификации.

**Каждый месяц** — обычный прогон `run_sa.py`. Для рядов с `freeze = TRUE` модель и
коэффициенты берутся из `sa_specs`, история не переоценивается; новые выбросы
ищутся только **после** границы заморозки и видны в колонке `new_outliers` сводки.
Код сам проверяет, что X-13 действительно взял замороженные коэффициенты, что
состав регрессоров совпал и что история периода идентификации не менялась (если
Росстат пересмотрел данные — предупредит, что ряд надо переидентифицировать).

В начале следующего года идентификацию повторяют, сдвинув `cutoff_date` на новый
декабрь. Старые файлы спецификаций при этом перезаписываются.

Заморозка сокращает пересмотры примерно втрое, но не убирает их полностью: когда
приходит, скажем, новый июль, фильтр SEATS уточняет июльскую сезонность и прошлые
июли слегка сдвигаются. Это свойство самой методики, так же ведёт себя и ЦБ.

Побочный эффект приятный: с заморозкой ежемесячный прогон идёт **быстрее** (модель
уже известна, X-13 ничего не подбирает) — на 44 рядах около 8 секунд против 90.

### Две ручки: `run_sa.py` и колонка `freeze`

Они не дублируют друг друга, а отвечают на разные вопросы:

| | отвечает на вопрос | как часто трогать |
|---|---|---|
| п. 0б в `run_sa.py` | **когда** переидентифицировать модели | раз в год: раскомментировать, запустить, закомментировать обратно |
| колонка `freeze` | **для каких рядов** использовать заморозку | один раз при настройке файла |

Идентификация обрабатывает только ряды с `freeze = TRUE`, и ежемесячный прогон
применяет спецификации тоже только к ним. Если заморожены все ряды — поставили
`TRUE` в строке `DEFAULT` и больше в эту колонку не заглядываете.

**Когда `freeze = FALSE` для отдельного ряда:**

- ряд с `tariff = schedule` (ЖКУ) — там нет модели, замораживать нечего;
- новый ряд короче трёх лет — идентификация требует минимум 36 месяцев;
- ряд, с которым вы ещё экспериментируете и подбираете настройки, — его нужно
  пересчитывать заново каждый прогон;
- ряд, историю которого пересмотрел Росстат, — код предупредит, что коэффициенты
  оценены на других данных; можно временно снять заморозку, пока не дошли руки
  переидентифицировать.

**Важно:** не запускайте п. 0б каждый месяц. Он не «дозамораживает», а
переидентифицирует заново и перезаписывает файлы спецификаций — если делать это
ежемесячно, модель будет меняться каждый месяц и смысл заморозки пропадёт.

### Первая точка ряда

Для `input_type = mom_index` X-13 сезонит уровень цен, а на выходе нужны темпы.
Поправка месяца — это **изменение** сезонного фактора, а для самой первой точки
предыдущего месяца в выборке нет. Код оценивает недостающий фактор по тому же
календарному месяцу следующего года (сезонные факторы меняются медленно), поэтому
первая точка считается так же, как все остальные. Без этого она уезжала бы на
величину сезонного фактора — обычно 0.2–0.6 п.п.

Тем не менее первый год выборки X-13 оценивает односторонним фильтром (слева данных
нет), так что он всегда менее точен, чем середина ряда. Если есть более ранние
данные — лучше подать их в файл, даже если сами эти годы вам не нужны.
Для `input_type = log_level` и `level` вопрос не возникает: на выходе сам уровень.

## Тарифы ЖКУ

`tariff = schedule` — для ряда, который **сам является** тарифами (колонка ЖКУ).
X-13 не используется; по методике ЦБ годовой рост ряда размазывается ровно по 12
месяцам календарного года: SA каждого месяца года Y = (рост за Y)^(1/12).
Для истории берётся факт из самого ряда, для незакрытого текущего года — факт по
последний месяц × план на оставшиеся месяцы с листа `tariff_plan`. Когда приходит
фактический месяц индексации, годовой итог уточняется и все месяцы этого года
чуть пересматриваются — так же живёт ЦБ.

`tariff = regressor` — для **агрегата, внутри которого сидят ЖКУ** (услуги целиком,
ИПЦ). В X-13 добавляется регрессор из графика индексаций (факт из колонки
`tariff_series` + план), центрированный внутри календарного года; коэффициент
при нём оценивается (≈ доля ЖКУ в агрегате) и эффект вычитается из SA-ряда.

Лист `tariff_plan` в `russia_calendar.xlsx`: колонки `date` (месяц индексации) и
`pct` (средняя индексация, %). Новый год — дописать строку.

## Отличия от R-версии

- Интерфейс `sa_ru()` тот же (те же названия настроек); `transform_function`
  переименован в `transform`.
- Добавлено: `input_type`, пакетная обработка из Excel, настройки в Excel,
  тарифные режимы, `include_easter = auto`.
- Заморозка перенесена и усилена: как в R-версии v3, фиксируются не только
  спецификация, но и коэффициенты; вызывается пакетно (`sa_ru_identify_batch`),
  спецификации лежат в `sa_specs/<имя ряда>.json`.
